- **Стыковка №1/№2 (`bidir_value`, hub-worker-5):** обратное дерево — Дейкстра (V точные), прямое — A* по g+est(p), est = min_b[V(b)+λ·|p−b|]; V(старт)=min[g+est]. Маятник u=.3, 8 запросов: V/Vfine mean 0.46…0.89 (λ 1…2.5, NB/NF 100…800) — **систематически занижено**, не монотонно улучшается; «цена зазора» λ·d без модели динамики не даёт верхней оценки (Δω=1 стоит ≈1/u≈3.3 времени, Δθ — иначе). Вывод: стык по расстоянию — нерабочий; нужен точный стык (двухточечная задача переключения: слой s из p до кривой обратной цепочки, «клетка» с точным пересечением) либо Делоне только внутри малых симплексов. Рабочий остаётся `build_tree` с T_max. Тест: `tests/check_adaptive_pend_bidir.py`.
- **Точная стыковка пересечением (research №4, `cross_value`, hub-worker-5):** обратное дерево — дуги-подотрезки с точным V, из прямых спор каждым слоем ищется пересечение (реальная траектория ⇒ верхняя оценка). Маятник u=.3, 8 запросов, τ=.25, rho .15: там, где стык найден, V/Vfine = 0.85…1.08 (не «занижает», как Делоне/расстояние; <1 — переключение внутри шага τ лучше квантованной эталонной V), при NB 100…800, NF 25…200 стык найден у 4–6 из 8 запросов (у остальных inf: трём-четырём переключениям нужны цепочки глубже; прямое дерево «мало переключений раньше» до них не доходит), при росте NB/NF покрытие растёт медленно, счёт в чистом Python ≈ минуты на 32 конфигурации. Вывод: метод честный и монотонный, но покрытие 1D-цепочек ↔ 1D-дуг в 2D требует ветвления обратного дерева по слоям на глубину 3–4 переключения; нужна (а) быстрая (векторная) проверка пересечений, (б) обратное дерево с большим NB и ядром по слою в масштабе (не rho·u по ω), (в) прямое A* с приоритетом «расстояние до дуг». Тест `tests/check_adaptive_pend_cross.py`.
