# Атлас дифдрайва v6: откуда худшие 1.23 и как мельчить (hub-research-1, 2026-09-30)
**Вопрос:** `solve_dd` (ромб-U, h = .25, nth = 24, τ = h) даёт V/эталон mean 1.037, max 1.232 (эталон min(TGT, TGTGT), 40 поз). Откуда max и лечится ли мельчением?
**Ответ:** худшие — не «змейка», а позы почти по курсу (|θ| < 0.2, |xy| ≈ 1.5; из 7 поз > 1.1 змейка лишь 1). Мельчить надо **(x, y)**;
мельчение одной θ **вредит**; окно цели, привязанное к шагу сетки, при мельчении раздувает V. Сходимость при согласованном мельчении медленная.
**Проверка** (`reports/research/dd_tau_per_layer.py`, `dd_refine_together.py`, солвер worker'а без правок; V/эталон mean / max):
| конфигурация | mean | max |
|---|---|---|
| h .25, nth 24 (по умолчанию) | 1.037 | 1.232 |
| h .25, nth 48 / 96, окно Rθ = hθ | 1.107 / 1.541 | 1.433 / 2.486 |
| h .25, nth 48 / 96, окно Rθ = .26 закреплено | 1.083 / 1.088 | 1.348 / 1.351 |
| + τ поворота кратно hθ (nth 48 / 96, Rθ = .26) | 1.080 / 1.089 | 1.367 / 1.367 — не помогает |
| h .125, nth 52, окно = h, hθ (по умолчанию, согласованно) | 1.033 | 1.171 |
| h .125, nth 24 / 48, окно .25 / .26 закреплено | 0.937 / 0.919 | 1.021 / 0.979 |
Значения < 1 — не выигрыш: широкое окно цели (.25 / .26 рад) позволяет остановиться раньше, а эталон ведёт точно в (0, 0, 0).
**Вывод:** (1) ошибка сидит в интерполяции по (x, y) на прямых (τ на слой не влияет — `v6_value_tau.md`); (2) окно цели задавать в
физических единицах, не через шаг сетки; (3) для честной сверки эталон должен вести в то же окно — min эталона по позам цели внутри окна
(сдвинуть старт относительно каждой позы окна; `tgt` дёшев, `tgtgt` — только у малых |θ|/боковых сдвигов).
**Что нужно worker:** окно цели — физический параметр; мельчить h (θ-сетку вслед за h, как сейчас); эталон «до окна» вместо «в точку».
