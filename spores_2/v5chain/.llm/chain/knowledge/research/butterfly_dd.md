# Споры-«бабочки» на дифдрайве (hub-v5chain-research-9, 2026-10-03; `reports/research/butterfly_dd.py`)
**Вопрос:** как перенести бабочки на дифдрайв (x, y, θ), управление (v, ω) в ромбе |v| + |ω| ≤ 1, цель (0,0,0). **Ответ:** спора = точка (x, y) ×
окружность курсов (m узлов V по θ); дуги в соседние споры — формулой; 4000 спор — 100% стартов, T/эталон 1.064 (мед. 1.055, max 1.21).

## Почему так
Дуга с постоянным (v, ω) зависит только от (L = v·t, φ = ω·t) ⇒ из позы в заданную ТОЧКУ (x_c, y_c) ведут ровно две дуги (передом/задом), курс
прихода определён. Поверхность приходов двумерна, курс в точке ей трансверсален ⇒ «нормальный отрезок» споры = весь круг курсов.
Обратная задача (в теле позы хорда (dx_b, dy_b)): передом α = atan2(dy_b, dx_b), φ = 2α, L = ρ·α/sin α; задом α' = atan2(−dy_b, −dx_b),
φ = 2α', L = −ρ·α'/sin α'. Время (ромб) t = |L| + |φ| — аддитивно, т.е. дуга стоит столько же, сколько «поворот + прямая» той же длины.
Проверка: 1000 случайных дуг — 0 промахов (1e-9). Плюс повороты на месте внутри споры (t = |Δθ|). Беллман — Якоби, V_c линейно по θ.
Эталон: min(TGT, TGTGT) (`dd_rhombus_ref.py`, `dd_rhombus_ref.md`), 60 стартов (x, y) ∈ [−2, 2]², θ равномерно; споры в [−3, 3]², окно 0.6, m = 24.

- Сходится с числом спор; V самосогласована (V ≈ T агента). Грабля (исправлено): поворот «на 0» в агенте давал ничью с V узла ⇒ вечный цикл
  (дошли 15%); запрет поворота на 0 — 100%.

## Эталон с 2 дисками (research-10, `reports/research/dd_obst_ref.py`)
Довод: обход диска ρ на угол β ломаной с поворотами на месте → ρβ + β = время дуги по ребру ромба (v = ρω ⇒ (ρ+1)β) ⇒ граф «прямые (передом/задом) +
повороты на месте» не теряет дуг. Граф: цель + KB точек на окружностях r/cos(π/KB) (хорды вне дисков) + сетка NG² (вершины TGTGT); цена по рёбрам
с курсом, итерации по узлам. Без дисков (NG 21): 1.0018 от точного min(TGT, TGTGT), max 1.019 (верхняя оценка, сетка). С дисками NG 21, KB 60:

## Ошибка модели дифдрайва (hub-v5chain-worker-15, 2026-10-04; `v7/reports/bdd/err.py`, N=1500, RW .9, 60 стартов dd_ref_60, без финиша TGT)

## Оценка ĝV, ĝW при ошибке привода (hub-v5chain-worker-16, 2026-10-04; `v7/reports/bdd/err.py`, EST=1; N=1500, RW=.9, 60 стартов, те же dd_ref_60)
EST=1: после каждого сегмента ĝW = набег курса/команда (повороты и дуги), ĝV = хорда/номинал (прямые); следующие команды делятся на ĝ; время = длительность команды. Исправлена ошибка учёта времени (сначала считалось по номиналу — давало ложный выигрыш).
| ошибка | без EST: дошли / mean / max | EST=1: дошли / mean / max |
| ω·.9 (GV=1) | 73% / 1.334 / 1.99 | **100% / 1.147 / 1.47** |
| v·.9 (ω=1) | — | 100% / 1.286 / 1.78 |
| .95/.95 | 100% / 1.107 / 1.21 | 100% / 1.214 / 1.50 |
| .9/.9 | 100% / 1.166 / 1.28 | 100% / 1.316 / 1.62 |
**Вывод:** оценка лечит ошибку по ОДНОЙ оси (ω·.9: потерянные 27% стартов возвращены), но при равномерной потере (.95/.95, .9/.9) хуже простой замкнутой пересчётки (сегментов 9 против 25 — прямая подгонка команд даёт длиннее путь). Нужно: применять ĝ только при |ĝV−ĝW| > порога, либо атлас на метрике |v/v̂|+|ω/ω̂| ≤ 1 (PLAN п.2). Не проверено на N=4000 и других сидах.
**EST=2 ARCV=1 (там же, лучший вариант):** оценки ĝV (по хорде любого сегмента) и ĝW (по набегу курса) считаются всегда, но компенсируется только РАЗНИЦА осей (команда делится на ĝ/√(ĝVĝW)), и только когда оценены обе оси. N=1500, RW=.9, 60 стартов: ω·.9 — **100% / 1.141 / max 1.44** (без EST 73% / 1.334); v·.9 — 100% / **1.127** (без EST ≈1.29 с EST=1; v·.9 без EST не мерен); .95/.95 — 1.107 (= без EST); .9/.9 — 1.166 (= без EST). Т.е. EST=2 не хуже простой пересчётки нигде и лечит ошибку по одной оси. Не проверено: N=4000, другие сиды, шум измерений. Запуск: `ARCV=1 EST=2 RW=.9 GV=.9 GW=1 python3 reports/bdd/err.py 1500` из spores_2/v7.
**Проверка EST=2 ARCV=1 на N=2500 (те же 60 стартов):** ω·.9 — без EST 77% / 1.355 / max 2.12 → **100% / 1.127 / 1.36**; v·.9 — без EST 100% / 1.249 / 1.68 → **100% / 1.114 / 1.28**. Подтверждено на втором N; N=4000 и шум измерений — не проверены (старты те же 60, сид менять нельзя: эталон dd_ref_60).
**Шум измерений состояния (`SIG=σ` в err.py: агент видит y+σ·N(0,1) по x, y, θ; цель по истинному; N=1500, ω·.9):** σ=.005 (≪ TOL .03) — без EST 100% / **mean 2.995** / max 9.9; EST=2 — 2.946 / max 8.95; σ=.02 — EST=2 5.415 / max 26. Т.е. дифдрайв-бабочки чувствительны к шуму сами по себе (T ×3 уже при σ=.005, EST тут не при чём): агент гонится за шумом у цели (V круто падает). Нужен фильтр состояния/мёртвая зона у цели — отдельная задача, не решена.
