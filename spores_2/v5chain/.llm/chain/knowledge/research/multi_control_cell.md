# Клетка, обобщающая все управления, а не один канал (hub-v5chain-research-29, 2026-11-11; задача пользователя). ВСЁ НИЖЕ — ГИПОТЕЗЫ до замеров
**Вопрос.** Сейчас атлас = отдельный слой клеток на каждое значение управления (3^m слоёв: маятник 3, кар 6–9, 3 мотора 27, 8D — 81). Можно ли одной клеткой
охватить все управления и за счёт этого уменьшить число клеток?
**Ответ одной фразой.** Главный множитель числа клеток — число слоёв L, а не размер клетки; убрать его можно тремя способами (В1–В3), самый дешёвый в проверке — Д1/В3.

## Счёт (арифметика): клеток ≈ L · (объём поля / объём клетки). Узел в слое u нужен только там, где оптимально идти с этим u; у задачи быстродействия
оптимум кусочно-постоянен, значит у каждой точки поля «свой» слой один (кроме границ переключения). Доля нужных клеток ~ 1/L + окрестности поверхностей переключения.
## Д1 — диагноз на готовых атласах (первым, без нового кода роста)
Для каждой клетки каждого слоя: доля её узлов, где argmin_u в уравнении V равен собственному u клетки («клетка работает»), и доля запросов бенча, чьи траектории
через неё проходят. Таблица: слой | клеток | работающих (>10% узлов) | на путях. Затем выбросить неработающие, пересчитать V, запросы: дошли, T/T_ref.
Ожидание: останется ~(1–2)/L клеток при том же качестве. Если нет — записать, где нужны «чужие» клетки (число, картинка).
Отличие от старого PRUNE (рост ×1.7–1.9): тот отсекал при построении по эллипсу запроса; здесь — по использованию политикой, для всего поля.
## В3 — один атлас, выровненный по оптимальной политике (следует из Д1)
Итерация: (1) грубый атлас слоями, V; (2) u*(x) = argmin; (3) новый ЕДИНСТВЕННЫЙ слой: клетка растёт потоком u*(семени) и останавливается на поверхности переключения
(там, где u* на её фронте меняется) — стоп-причина «смена режима»; (4) V на нём; повторить 1–2 раза. Рёбра вдоль оптимальных дуг точные (концепция сохраняется:
«ребро своего u точное»), переключение — переход в соседнюю клетку другого режима. Клеток ~ в L раз меньше. Риск: политика грубого атласа ошибочна у поверхностей
переключения — нужна полоса клеток обоих режимов вдоль них (толщина = неопределённость поверхности).
## В2 — одна клетка с локальной моделью по управлению
Клетка = сечение (n−1) × время вдоль опорного потока (дрейф u = 0 или u*), в ней модель Φ(c + δ, t, u) ≈ квадратичная по (δ, u) (для аффинных по управлению систем
зависимость от u на коротком τ почти линейна: Φ ≈ Φ₀ + t·B·u). Узлы одни на все управления; ребро для любого u — по модели + интерполяция V (полулагранжева схема
на адаптивных клетках). Клеток в L раз меньше, управление можно брать непрерывным. Плата: ребро «чужого» u — интерполяционное, а не точное ⇒ размазывание V (то, от чего
уходили). Проверка: маятник — T/T_ref против 3-слойного атласа при том же числе узлов.
## В1 — «воронка»: координаты клетки (s, t, u), x = Φ_u(c + s·N, t), сечение размерности n − 1 − m
Это «бабочки» (concepts: D = [∂Φ/∂t, ∂Φ/∂u]). Одна клетка покрывает конус достижимости сечения. Вырождение в вершине: при t → 0 все u совпадают (∂x/∂u ~ t·B),
у вершины нужны регулярные координаты (t, w = t·u) и минимальное t₀; конусы плохо стыкуются (щели у вершин). Прошлый опыт бабочек: 1509 спор против 258 у клеток-слоёв
на ДИ (`grow_cells.md`) — хуже. Не первым.
