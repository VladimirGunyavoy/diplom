## Проверка конвейером (`r23/03_manip_pipeline/`, d3c3000: GS 0, GLIM 0, DELTA .3, 4×3000, 2.17M узлов, build 276 с, покрытие слоя .54–.59, |w| ≤ 1 .78–.90)
- **Провал: solve 28 проходов (1367 с, стенсилы на CPU), конечных .001, дошли 0/20.** В цели 58 узлов (c3000 с GS 300 — 74 645; снаружи ближе .05 — 124 против 58 621): затравки в цели пропускаются, рост стоп у её границы (GOALB) ⇒ при посеве без затравок у цели у V нет источника (цель — 2.5e-4 объёма поля). **GS=0 нельзя; GS (затравки у цели) — граничное условие, GLIM .25 (мелкие клетки у цели) — не нужен.**
- Открыто: FIFO-очередь от затравок GS не пустеет (c3000: 34k) ⇒ посев фактически BFS от цели и зависит от порядка (против концепции «повсеместно, параллельно»). Идея (не проверена): GS только как источник, очередь — со случайными затравками вперемешку.

- **Источник есть, связности нет:** b6 g50d3 (GS 50): в цели 2545 узлов, V до 5.05, но конечна в 1.1% узлов (`r23/03/vdiag.py`; c3000 — 77%). Гипотеза: `PESS` не задан (−1) ⇒ стенсил с хоть одной неизвестной вершиной = BIG; в di4 это лечили `PESS=1` (research-18). **ПОДТВЕРЖДЕНО** `r23/05_manip_pess/` (те же слои g50d3 + `PESS=1 WTHR .5`): 415 проходов, конечных **.981**, **дошли 20/20, T/эт к OCP мед. 1.089 / ср. 1.150 / max 1.50** (хвост — старты 5, 8, 19, 20), запрос 171 мс, solve 1523 с (стенсилы на CPU по протоколу GPU ~20 мин).
- **Хвост g50p1 — V занижена, не агент** (`r23/05/vstart.py`, `vspread.py`): V*/эт на стартах 3 / 5 / 19 / 18 / 0 = .44 / .68 / .68 / .86 / .87 (ниже T*, физически невозможно), агент хуже всего там же (5: 1.50, 19: 1.47, 18: 1.31). Эталон устойчив (15 затравок на ветвь — то же T). Все 5–15 стенсилов старта согласны (разброс ≤ .06), неизвестных вершин 0 ⇒ не min по стенсилам и не PESS; занижена V в узлах. Гипотеза: ошибка полилинейной интерполяции V на крупных клетках (M 3 поперёк, r до .6) + min по u на ~30 шагах ⇒ систематический сдвиг вниз. Проверка — DELTA .1 (`r23/05/run_d1.sh`, g50d1p1), затем M 5.
- **DELTA .1** (g50d1p1, GS 50, PESS 1, 4×3000, 2.47M узлов, build 250 с, solve 1655 с с CPU-стенсилами): **20/20, T/эт мед. 1.076 / ср. 1.109 / max 1.51**, запрос 221 мс; хвост 5 / 8 / 18: 1.50 / 1.41 / 1.31 → 1.18 / 1.11 / 1.03, старт 19 — 1.51. **V*/эт на 3 / 5 / 19 — .48 / .67 / .74 (то же, что при DELTA .3) ⇒ размер клеток не причина занижения.** Следующая гипотеза — min по перекрывающимся стенсилам в solve (как di4, research-22 п.43): `SMEAN=1` на тех же слоях — `r23/05/run_sm.sh` (идёт).
- **Где занижение — у границы цели** (`r23/05/vtrace.py`: жадный спуск по V*, должно быть V*+t ≈ const): старт 3 — V* ≈ 1.4 держится первые 1.3 с манёвра у цели (goal_dist .25–.5), V*+t растёт 1.4 → 3.1 (реально 3.1); старт 5 — у цели V* .73 при реальном остатке 2.3. `goalw.py`: в слое goal_dist .05–.15 у 41% точек вес вершин-узлов цели (V = 0) в стенсиле > .1, V* мед. .36 ⇒ **V разрывна на границе коробки цели (снаружи, при скорости наружу, V велика), полилинейная интерполяция размазывает 0 наружу (клетки r до .6 > полуширины цели .3), solve несёт заниженное назад по траекториям.** GLIM (мелкие клетки у цели) был против этого. Исправление-прототип `GOALX=1` (копия growN `~/spore_v5/r23/07_goalx/`): узлы цели не интерполировать (solve GPU и vstar), вход в цель — точно через tgoal; прогон g50gx — `r23/07_goalx/run.sh`.
- **SMEAN=1 не лечит** (те же слои DELTA .1, `r23/05/run_sm.sh`): V*/эт на 3 / 5 / 19 — .61 / .78 / .90 (всё ещё < 1), на остальных V завышена до 1.1–1.5; агент 20/20, мед. 1.110 / ср. 1.133 / max 1.50 — хуже, чем без SMEAN (1.076 / 1.109); запрос 169 мс, solve 1342 с.
- **GOALX не лечит** (`r23/07`): V*/эт 3 / 5 / 19 — .49 / .67 / .75 (было .48 / .67 / .74), агент ср. 1.110, max 1.46 ⇒ прямая утечка 0 цели — не главное.
- **Причина — гиперячейки поперёк излома V** (`r23/05/kink.py`, спуск от стартов 3 и 19): у min-стенсила V по вершинам от .05 до 2.5 (размах 1.3–2.5 с внутри ОДНОЙ гиперячейки), интерполянт ниже Беллмана B(y) = min_u DTN + V*(шаг) на КАЖДОМ шаге (+.03…+.17 за DTN .1) ⇒ дрейф V*+t ~.6–1 за секунду. Время быстродействия = min по стратегиям ⇒ вогнутые изломы на поверхностях переключения; линейная интерполяция вогнутой функции лежит ниже неё, solve копит это вдоль пути. DELTA не меняет (продольный шаг DTN·|f| и ширина гиперячейки ≈ те же). **Лечение по концепции — адаптивное дробление клеток там, где велик остаток Беллмана / размах V по вершинам (АТЛАС §7 «дробление по ошибке цены»)** — PLAN п.46.
