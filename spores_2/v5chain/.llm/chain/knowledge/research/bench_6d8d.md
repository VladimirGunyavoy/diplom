# bench 6D/8D (линия A, worker-27, 2026-10-13) — итоги и грабли
Таблицы: `reports/bench/table_m3d.md` (3D двузвенник), `table_m3g.md` (3 зв.+g, вниз/вверх), `table_m8.md` (4 зв. 8D+g). Данные `reports/bench/data/m*_`, код `spores_2/bench/{envs_6d,spores_6d,spores_8d,ocp_6d,make_report_a,rescore_m8,sync_6d}`.
- Споры (коридор v6) держат T ≈ эталон (мед 1.00–1.04), но запрос 6 с (m3d) … 40–105 с (3g) … ~1000 с (8D, aida нагружена), заготовка 4–48 с (8D: 1500–1700 с, 590 МБ). OCP CasADi multistart: 12–37 с при том же качестве ⇒ в 6D споры быстрее OCP-multi максимум ×2 (m3d), на 3g — медленнее. OCP «ближайшая ветвь» 1–2.5 с, но T хуже (1.05–1.6) и 35–90% доходимость. PPO: 0.02–0.07 с на запрос, доходимость 98/33% (3g вниз/вверх), 28% (8D), T ≈1.5–2.4. SST 0–55% за 60 с.
- Грабли: (1) эталон OCP ограничивает |w|≤3 только в узлах N=50, внутри интервалов до 3.05 ⇒ допуск |w| .01 (m3d) / .05 (3g, 8D) для ВСЕХ методов; (2) refine коридора держит |w|≤3 только в узлах ⇒ без `wlim` споры на 3g ловят 'box' (10–30%); честный вариант — с `wlim` (запрос ×1.5–2); (3) T_ref для 3g «вверх» — best известное (r5), неопределённость до 6%; для 8D эталона нет — T_ref = лучший найденный среди методов (OCP multi даёт большинство ⇒ его отношение ≈1 по построению); (4) времена снимались при загрузке aida 12–25 из 32 ядер.
- Вывод для цели «споры быстрее всех»: на этих средах НЕ показано; заявимо «качество = эталон, одна заготовка на цель»; выигрыш на запрос нужен от ускорения запроса (SLSQP-refine — основной расход) — задача для линии скорости.
