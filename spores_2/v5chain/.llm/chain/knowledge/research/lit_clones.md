# lit_clones — клоны/периодические копии (θ маятника, 2π) в v4…v8 (searcher-5, 2026-10-13)
Вопрос (слово пользователя: «нужно клонирование, а не резкий переход в другой экран, задача циклическая»): как делались периодические копии в визуализации и в расчёте.
**Ответ.** Один приём везде: узлы/клетки хранятся в «развёрнутом» θ, а копии со сдвигом SH=(0,+P,−P) (P=2π) считаются только в индексе/запросе; точка запроса wrap'ится в [−π,π), клетка пробуется во всех копиях. В визуализации — то же: отрезок/треугольник через шов режется/дублируется со сдвигом ±P. В v4_ort/v4_circle (ursina-движок) и v1–v3 периодичности нет (grep: seam/wrap/torus/цилиндр — пусто; «клоны» там = ghost-споры/боковые траектории, не копии).
## (б) РАСЧЁТ (v7 — эталон; v8 — копия)
- **Система**: `v7/src/cells7/growN.py:22` pend: `PERIOD=[2π,0]`, XLV[θ]=0 (по θ границы поля нет); `:60–64` `PER, NP_`, `SH` = декартово произведение (0,±P) по периодическим осям (pend 3 копии, manip 9, 6D 27), `KSH=len(SH)`, `wrapy`. v8 — те же строки `v8/src/algo/growN.py:72–76`.
- **Индекс ячеек** (`growN.py:145–165`, v8 `:229–236`): ящик гиперячейки [lo,hi] сдвигается на каждый SH; копия берётся, только если пересекает [−P/2−QB, P/2+QB]; в бины QB^n кладётся `hid*KSH+si` (номер ячейки + номер копии).
- **Locate/query** (`:187`, `:216`, v8 `:261,:290`; `_pquery :373`, `:399`): `Y=wrapy(Y)`; кандидат (hid, si) → `y = Y − SH[si]` → проверка по LO/HI и Ньютон в локальных координатах. То есть «ленивой решётки клонов» как отдельной структуры нет — клон = (ячейка, индекс сдвига), память не множится, множится только число бинов.
- **Агент/посев**: `wrapy` после каждого шага (`:539`, v7 grow3 `:340`), `rand_seed` ∈ ±P/2 (`:300`), `ingoal=wrapg` (`:88–89`), финиш-стрельба `finish_gen.shoot_*` принимает `wrapy` аргументом. Рост клеток идёт в развёрнутом θ (клетка может выйти за ±π — это нормально).
- **2D-ветка v7** `grow_cells2d.py`: `PER=2π`, `SH=(0,PER,−PER) :34`, `wrap :25`; бины `:104–109` и `:162–165` хранят пары (клетка, sh), пропуск копий вне `[−XL−.2, XL+.2]` (`:105`, `:163`, `:626`, `:647`); locate по четырёхугольникам с `y = Y − (sh,0)` (`:144,:147`); `inbox` при PER не ограничивает θ (`:32`). Барьер/стены CUT: `nearb` делает `wrap(P[:,0])` перед KD-запросом (`:181`) — стена на шве работает через wrap, копий стены нет (`BARRIER` хранится в [−π,π)).
- **Старше**: v6 `atlas6/pend.py:10,19` — сетка θ∈[−π,π) и `wrap`; `adaptive_tree.py:16,261` — `wrap`/`wrapd` (кратчайшая разность по кольцу), бины по `cellk(S.wrap(.))`; клонов нет. bench: `common.wrap(d,period)` (`bench/common.py:7`), ompl `SO2StateSpace`, ocp_casadi — две ближайшие обмотки цели (`:44–46`).

## (а) ВИЗУАЛИЗАЦИЯ
- **Единственная реализация — v8 (worker-9, 25d4e56)**: `v8/src/stepper/growview.py:137` `WRAP_X` (включает `main_pend.py:141` = 2π); `wrap_lines :140` — отрезок с |Δx|>P/2 режется в точке шва на два куска в ближайших копиях (цвет интерполируется); `wrap_tris :160` — треугольник с разбросом x>P/2 дублируется в две копии (вершины x<0 → +P / x>0 → −P), без растяжки через экран; вызов в `_geom_node`-обёртке `:206–208`. Это и есть «клон, а не переход в другой экран» — копии рисуются за краем ±π (за краем должны быть видны).
- Нет: рисования ±2π-копий **всей** сцены/поверхности V целиком, тора/цилиндра, копии камеры; треугольники рвутся только по порогу P/2 (треугольник, покрывающий шов целиком шире P/2, но тонкий — не поймёт; ячейка шириной >π тоже).
