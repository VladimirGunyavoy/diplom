# Схема Б: однопроходной label-setting для локального пересчёта V (research-31, 2026-11-11 06:30)

сходится за ~30–47 проходов (6–10 с). Уложится ли ОДИН упорядоченный проход (Дейкстра) в ≤ 1 с при той же V?
**Ответ:** да — label-setting с инкрементными суммами рёбер: 0.87 с на области 441k узлов, V к сошедшемуся GS мед +.001 / p90 +.04;
+1 проход GS (0.21 с) → p90 +.007, p99 +.026. Схема Б по времени ЖИВА; решает теперь только p90 агента (задача b16).

## Алгоритм (`reports/research/r31/lsk2_r31.py`, функция `ls`, numba, 1 поток)
Рёбра = стенсилы атласа (узел i, управление u → вершины X[e,0..15] с весами W), как в GS-sweep b16 (`bench/bk.py`):
val_e = DTN + Σ_acc w·V + (1 − Σ_acc w)·(max_acc V + pe), ребро годно при Σ_acc w ≥ WTHR (.5).
1. Подготовка (зависит только от области, не от дисков): обратный индекс «вершина области → (ребро, вес)» — 45M вхождений, 3 с numpy.
2. Вершины вне области — приняты сразу со значением V₀ (граница); их вклад внесён в суммы s_e, sm_e, mx_e заранее. Цель — 0.
3. Куча по tent; вынули узел → принят (V = tent); для всех его вхождений: s_e += w·V, sm_e += w, mx_e = max — O(1) на вхождение;
   пересчёт val_e владельца ребра, улучшение → в кучу. Запрещённые узлы (облако κσ(τ)) не принимаются никогда (V = BIG).
4. Каждое вхождение трогается один раз ⇒ работа ~ 45M операций + куча 270k узлов (4.1M улучшений).
Это не точная Дейкстра: интерполяция в 4D не причинна (узел принимается до части своих вершин) ⇒ V смещена; pe — цена недостающего веса.
