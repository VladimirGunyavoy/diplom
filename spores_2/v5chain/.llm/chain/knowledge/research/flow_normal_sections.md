# Нормальные (гипер)плоскости к потоку — как строить сечение клетки (research-24, 2026-10-07)
Задача пользователя (через laptop-v5chain-research-1, ~19:30): «как правильно строить многомерные нормальные плоскости к потоку — должно же быть что-то».
Литература — `lit_flow_normal_sections.md` (searcher-2). Проверка — `reports/research/r24/normal_sections_dd.py`.

## Ответ
«Честного» сечения ⟂ f, построенного шагами с пересчётом базиса, в общем случае **не существует**: при n ≥ 3 поле плоскостей f⊥ обычно неинтегрируемо
(Фробениус, ω∧dω ≠ 0), и точка сечения зависит от порядка шагов. Правильная конструкция — та, что в коде: **плоское сечение ⟂ f(зерно), перенесённое потоком**
(выпрямляющие координаты, flow-box). Ортогональность нужна только в зерне, дальше — лишь трансверсальность. Сечение оставить как есть (и в v8).

## Почему
- f⊥ — это ядро 1-формы ω = f♭ (метрика евклидова, как в `growN.basis`). Гиперповерхность, всюду ⟂ f, существует ⇔ ω∧dω = 0 (n = 3; n ≥ 4 — ω∧dω = 0 как 3-форма) —
  ABB 2019 Thm 2.37. Это условие на поле f; выбором алгоритма обхода оно не обходится.
- **Дифдрайв:** f = (v cosθ, v sinθ, ω), ω∧dω = −v² dx∧dy∧dθ — при v ≠ 0 f⊥ **контактное** (максимально неинтегрируемое, как группа Гейзенберга:
  петля по горизонтальным путям даёт сдвиг вдоль f ∝ её площади, ABB §4.4.3). У ромба |v| + |ω| ≤ 1 слои (±1, 0) — контактные, (0, ±1) — интегрируемые (f = ±∂θ).
  Смена метрики (масштаб θ против x, y, грамиан W⁻¹) контактность не снимает — меняет только константу.
- Плоское сечение Σ₀ + перенос потоком φ_t(Σ₀): каждой точке однозначно сопоставлены (координаты в Σ₀, время t) — это flow-box (Arnold, Lee гл. 9; не открыты
  searcher'ом, классика). Ни от какого порядка шагов не зависит; функция времени τ (∇τ·f = 1) задана точно. Сечения φ_t(Σ₀) при t ≠ 0 не ⟂ f (сдвигаются потоком) — и не должны.

## Проверка (дд, Евклид, рост на 200 подшагов с пересчётом базиса проекцией + Грам–Шмидт)
| слой (v, ω) | r | голономия (0 1) против (1 0), сдвиг вдоль f в ед. времени | радиальное − плоское | min cos(f(x), n₀) на плоском |
|---|---|---|---|---|
| (1, 0) | .1 / .2 / .5 | .010 / .040 / .240 (≈ r²) | .005 / .020 / .124 (≈ r²/2) | .995 / .980 / .878 |
| (.5, .5) | .2 / .5 | .030 / .193 | .010 / .061 | .995 / .969 |
| (0, 1) | любое | 0 | 0 | 1 |
Сдвиг ≈ r²·|ω∧dω|/|f|³ (подгонка по двум слоям — гипотеза, не вывод). При r .2 рассогласование порядков .04 ед. времени ~ 1% T дд, т.е. того же порядка, что мы боремся
за T/эт; при r .5 — 0.24 (≈ 6%).

## Варианты и вердикт
1. **Плоское ⟂ f(зерно) + поток (сейчас)** — точное, однозначное, полилинейная заплатка по углам согласована (углы лежат в плоскости, `bend` меряет только
   нелинейность потока). Трансверсальность на дд: cos ≥ .98 при r .2, ≥ .88 при r .5 — запас огромный. **Брать.**
2. **Шаги с пересчётом базиса по осям (0 1), (1 0), (1 1)…** — на контактных слоях дд зависят от порядка (таблица); ничего не даёт клетке. **Не брать.**
3. **Радиальное (единственный однозначный «кривой» вариант)**: точка (a, b) — путь по прямой w = a e₁ + b e₂ с проекцией направления на f⊥ в каждой точке
   (аналог субримановой экспоненты, ABB Def 8.34). Отличие от плоского ≈ r²/2 — поправка второго порядка; ломает полилинейную заплатку (углы не в плоскости →
   `bend` смешает кривизну сечения с нелинейностью потока). **Не брать.**
4. **Изохроны/изостабили** (уровни τ, Mauroy–Mezić–Moehlis 2013) и HHD (Bhatia 2013) — глобальные, требуют счёта на всём поле, ⟂ f тоже не дают; для задачи
   быстродействия «правильные фронты» — это уровни самой V (фронт эйконала), их мы и так получаем solve'ом.
5. **Где пересчёт базиса полезен — между клетками, не внутри:** новая клетка на продолжении старой (затравка у конца строки, NF-фронт) — оси брать переносом базиса
   родителя (проекция на f⊥ + Грам–Шмидт = RMF 1-го порядка; 3D — двойное отражение Wang 2008, O(h⁴)), а не свежим SVD: одинаковый порядок и знак осей у соседей
   (стыковка соседей, вид в v8). Гипотеза, не замерено.

## Сверка с концепциями (`concepts.md`)
Не противоречит: «клетка — полуширина r поперёк поля», «2 нормальные плоскости от споры, клоны их соединяют» (плоскость ⟂ f в зерне остаётся; соединяют её клоны
— потоком), «один алгоритм на все среды» (вариант 1 одинаков в любой размерности). Бабочки (нормальный сегмент = ядро Dᵀ, D = [∂Φ/∂t, ∂Φ/∂u]) — тоже плоский
объект в одной точке, тот же принцип.

## Что нужно worker'у
Ничего обязательного. По желанию: (а) страж трансверсальности — cos(f(угол), n₀) < .5 → стоп роста вбок с причиной «поворот поля» (2^(n−1) вызовов f на клетку);
(б) вариант 5 — оси дочерней клетки переносом базиса родителя, замер: доля стыков соседей с согласованными осями, T/эт, время.
