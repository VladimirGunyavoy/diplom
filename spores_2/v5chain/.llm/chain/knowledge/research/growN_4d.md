# growN в 4D: сколько клеток и почему (hub-v5chain-research-17, 2026-10-06 13:30; линии A — DI 4D п.24, B — манипулятор п.22)
**Вопрос:** клеток в 4D «взрыв» (DI 4D RMAX .5 FRAC .5 — 5820/слой, очередь 62k; манипулятор FRAC .5 — 10k+/слой, очередь 109k) — баг или норма?
**Ответ:** часть — дробление щелей остановкой по соседу (FRAC .5 → 1.0 даёт ×10 меньше клеток, w22); остальное — объём поля, `covered()` в 4D верен.

## Проверка и оценка
- `covered()` 4D (aida `r17/diag/cov4.py`, DI 4D FRAC 1 GLIM 0 RMAX 1, 40 клеток): 800/800 случайных точек ядер (|a| ≤ .9·r, пронесены на случайное число строк) покрыты.
- Клетка DI 4D: r ≈ .55 по всем 3 боковым осям (из RMAX 1), длина ~7 строк (.7 с) — время режет граница поля (v растёт со скоростью 1: физика DI, не лечится).
  Объём клетки ≈ (2·.6)³ · .7 · |f| (≈ 2.5) ≈ 3; поле с GM 1 — 7⁴ = 2401 ⇒ ~800 клеток/слой при наложении 1. Рост ~15 клеток/мин без насыщения — ожидаем.
- **GM в 4D дорог:** объём (5 + 2·GM)⁴/5⁴ — GM 1 ×3.8, GM .25 ×1.5 (у дд GM был по 2 осям из 3: ×1.96). DI 4D — GM .25; манипулятор — |w| ≤ WM физическая, GM нельзя.
- Масштаб (гипотеза): клеток ~ объём поля / (∏ 2r_k · L), при r, L ~ const — экспонента по n, как сетка, но с основанием (поле / клетка)^(1/n) ≈ 3–5, а не 50–100.
  Сократить: (1) крупнее клетки там, где изгиб мал (у DI изгиб = 0 — рост режет только сосед/граница); (2) поле — только трубка, нужная стартам (обратная достижимость цели ∩ окрестность стартов).
