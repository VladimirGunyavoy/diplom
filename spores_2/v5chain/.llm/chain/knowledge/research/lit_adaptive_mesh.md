# lit_adaptive_mesh — готовые методы адаптивного размещения узлов по значениям V (searcher-2 для research-3, 2026-10-12)
Обзор: `~/claude-work/system/library/reviews/2026-10_adaptive_mesh.md` (L1 MAP, карточки sources/). Прочитаны по тексту: Chebfun detectedge, Grüne 1997, Jakeman–Roberts §2–3; остальное — аннотации/сниппеты (помечено).
**Вопрос:** как автоматически ставить узлы там, где у V резкие неровности; поперёк потока интерполяция по 3 траекториям, изломы + скачки «попал/мимо», новый узел = 1 траектория.

**Ответ.** Все готовые методы сводятся к одному индикатору — ОСТАТКУ НОВОГО УЗЛА: |V_точное(середина) − интерполянт по старым узлам| (в 1D «ошибка в середине интервала», у Ma–Zabaras/Jakeman «hierarchical surplus», у Grüne — невязка Беллмана). У нас V_точное считается одной траекторией ⇒ оценщик не нужен, это прямая проверка. Делим интервал, пока остаток > tol; скачок и излом узнаются по тому, как остаток убывает с уровнем (гладко ≈4^-l, излом ≈2^-l, скачок ≈const); их локализуют бисекцией и узел/границу куска ставят НА них. Равнораспределение (de Boor) — для заданного числа узлов, в nD тяжело.

## Что применимо к нашей постановке (вывод searcher, решает research)
- Правило: стартовые 3 траектории → для каждого интервала/симплекса сечения считать остаток в середине (1 траектория, узел остаётся) → делить при остатке > tol; остаток по уровню: ratio ≈4 ⇒ гладко, ≈2 ⇒ излом, ≈1 ⇒ скачок → бисекция по метке, остановить деление, пометить границу куска.
- Огрубление после solve по Grüne (убирать узлы с остатком < tol) — экономит узлы без потери точности.
- Контроль хвоста: остаток мерить по max, не по среднему (как в вашем r17: хвост T растёт при прореживании).
- Риск: пропуск особенности между грубыми узлами; лечится доп. индикатором — разные метки соседних узлов ⇒ делить принудительно (см. lit_separatrix_detection).

Литературы про узлы-траектории поперёк потока с разрывной V и «V известна только после итераций»; сравнения остаток vs равнораспределение на функции времени.
