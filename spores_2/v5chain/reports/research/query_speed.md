# Почему запросы медленные — профиль corridor_query (research hub-research-3, 2026-09-30)
Задача — PLAN.md «research: почему запросы медленные». Код `src/` не трогался; прототипы и замеры — здесь.
Инструменты: `profile_query.py` (этапы, вызовы потока точка/батч, SLSQP по статусам, cProfile; режимы `SCALAR`, `FAST=seq`, `MAXIT`, `EARLY`),
`flow4_scalar.py` (поток манипулятора на `math`), `refine_fast.py` (`refine_seq`, `refine_fast`), сырые JSON — `query_speed_runs/`.
Запросы — те же seed/параметры, что в `tests/check_corridor_*.py` (dd NB1200/NF50/K5; маятник NB400/NF50/K5; манипулятор NB600/NF300/K3;
манипулятор+препятствия NB2400/NF400/K3). t — одно `corridor_query` (без build_back). Замеры на aida шли по 8–12 процессов параллельно
(±15–20% к одиночному прогону, сравнения внутри серии честные).

«Рекомендуемое» = скалярный поток для точки + `maxiter=80` + последовательные точки зазора (`refine_seq`); алгоритм кандидатов/топологий не менялся.

## Почему (по пунктам, с числами)
1. **Время — не в дереве, не в KD-дереве, не в Делоне.** build_back, _tree, tree_query, candidates (батч) — ≤ 3% запроса. ~98% — `refine` (SLSQP).
2. **SLSQP зовёт поток ОДНОЙ точкой.** Якобиан ограничения — конечные разности: n+1 полных проигрышей пути на итерацию, каждый — Python-rk4
   на векторе из 4 чисел. Цена вызова `flow4` (t=0.4, 8 шагов): numpy 1403 мкс хаб / 245 мкс aida; на `math` — 110 / 11 мкс (×13 / ×22),
   разница результата 1.8e-15. Маятник на `math` — побитно тот же rk4.
3. **Хвост maxiter.** Успешные SLSQP (maxiter 300): nit p50 8–9, p90 13–28, p99 20–56, max 33–100. Прогоны до maxiter=300 (status 9) — 1–3 на запрос, но
   17–55% времени (скалярный поток: 7.2 из 13 с на 2 запроса). maxiter 80: T тот же на 8/8 (манипулятор, маятник, препятствия); maxiter 40 — манипулятор q2 2.319 → 2.677 (хуже) ⇒ 80.
4. **Провальные топологии-промахи (status 8)** — 40% прогонов. Бросать топологию после первой недопустимой попытки (`EARLY`) — ✗:
   теряет решения (манипулятор q2 → None, маятник q8 → None, препятствия q4 3.34 → 3.86). Повторы tries=3 нужны.
5. **scipy 1.16+ (SLSQP переписан с Fortran на C)**: тот же запрос манипулятора — 22 тыс. вызовов потока вместо 72 тыс. (1.18 vs 1.11), ×2–3.
6. **Хаб ≈ 10× медленнее aida на одном ядре** не из-за нагрузки/BLAS: чистый Python-цикл 0.40 с vs 0.038 с, `sum(range(3e7))` 2.0 vs 0.19 с,
   memchr 4.6 vs 38 ГБ/с — одинаково при load 0.9 и 2.8, на любом ядре, cgroup без троттлинга, steal ~1%. KVM-VM на перегруженном хосте
   (гипотеза). Потоки BLAS не при чём: OMP/OPENBLAS не заданы, но матричных операций в запросе нет (вектора по 4 числа).
7. **SLSQP хаотичен:** разница потока 1e-15 меняет найденное T на трудном запросе (манипулятор q2: 2.319 ↔ 2.853 в одном из прогонов scipy 1.11).
   Качество коридора на трудных запросах — «удача» SLSQP; сравнивать версии кода только сериями запросов, не одним.
8. **aida масштабируется до 16 процессов**: 1 → 0.36 с, 16 → 0.43–0.46 с, 32 → 0.84–0.9 с (SMT не даёт). Пул из 16 процессов по запросам ≈ ×13.
9. Батч-якобиан (`refine_fast`: ∂x_end/∂dt_k = Φ·f_{s_k}(x_k), все столбцы одним батчем) — верен (сверка 1e-7), но с скалярным потоком
   проигрывает: батч numpy дороже нескольких вызовов на `math`. Полезен, только если поток остаётся numpy. Не рекомендую.

## Рекомендации worker'у (по убыванию выигрыша на единицу работы)
1. **Скалярный поток для точки** (`flow4_scalar.py` → `manip2dyn.flow4`; маятник — то же в `gcell.rk4`/pendulum; дд — формула на `math`):
   `if x.ndim == 1: <math-ветка>`, батч — как есть. ×7 (хаб) … ×20 (aida). Тест: разница с numpy ≤ 1e-12.
2. **maxiter 300 → 80** в `corridor_nd.refine`. Тест: check_corridor_manip_dyn / nd_pend — T те же.
3. **Точки зазора последовательно** (`refine_seq` в `refine_fast.py`): p_j = flow(p_{j−1}, t/ns). Препятствия ×4–6.
4. **Серии запросов — на aida, пулом из 16 процессов** (`multiprocessing.Pool(16)`, build_back — один раз до пула, в fork). ×13 пропускной.
5. **scipy ≥ 1.16 на aida** (сейчас 1.11.4 — системный; venv с 1.18 работает: `~/spore_v5/r3prof/venv`, но это решение fixer'а/пользователя).
6. Хаб — только для лёгких проверок (dd, маятник); манипулятор/препятствия — aida. Итог для манипулятора: 124 с (хаб) → ~1.2 с (aida) → ×100.
Дальше (если нужно ещё): якобиан зазора аналитически (dim 4+16·nseg — главный остаток на препятствиях); ns 16 → 8 с проверкой столкновений.
