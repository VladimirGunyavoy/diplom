# Атлас спор для двойного интегратора: как запрограммировать

## 1. Постановка

Система: ẋ = v, v̇ = a, |a| ≤ a_max. Задача — быстродействие: попасть из (x₀, v₀) в цель за минимальное время.

Идея атласа:

- у каждого экстремального управления (a = +a_max и a = −a_max) есть своё семейство траекторий, и в своих координатах оно выпрямляется точно;
- споры — это ячейки в этих выпрямляющих координатах;
- места, где споры разных семейств пересекаются, — это узлы переключения;
- поиск оптимального пути — это поиск кратчайшего пути по графу «движение вдоль траектории + переключение».

Для двойного интегратора у схемы есть точный эталон (синтез с одним переключением), поэтому он удобен для отладки перед переходом к дифдрайву.

## 2. Выпрямляющие координаты

При постоянном a траектории — параболы x = c + v²/(2a). Номер параболы — первый интеграл:

| Режим | Номер траектории | Координата «вдоль» | Скорость вдоль |
|---|---|---|---|
| a = +a_max | c = x − v²/(2a_max) | v (растёт) | v̇ = +a_max |
| a = −a_max | d = x + v²/(2a_max) | v (убывает) | v̇ = −a_max |

Физический смысл: d — точка остановки при торможении, c — точка, где скорость была нулевой при разгоне.

### Пара (c, d) как карта плоскости

Парабола c из «+» семейства и парабола d из «−» семейства пересекаются в точках

    x = (c + d) / 2,   v = ±√(a_max · (d − c)),   при d ≥ c.

То есть (c, d, sign v) — глобальные координаты на фазовой плоскости. Прямоугольная сетка по c и d автоматически даёт:

- «+» споры — полосы между соседними c_i, c_{i+1};
- «−» споры — полосы между соседними d_j, d_{j+1};
- их пересечения — ячейки [c_i, c_{i+1}] × [d_j, d_{j+1}] (отдельно для v > 0 и v < 0);
- узлы решётки — точки переключения.

**Особенность:** на линии d = c (ось v = 0) карта складывается: v = ±√(…), и производная по d − c бесконечна. Рядом с v = 0 интерполяция в (c, d) плохая — см. раздел 7.

## 3. Структуры данных

- `C`, `D` — отсортированные массивы номеров парабол (сетка). В них **обязательно** добавить параболы, проходящие через старт и цель: c_start, d_start, c_goal, d_goal. Тогда точное решение гарантированно лежит в графе.
- Узел: ключ `(i, j, s)`, где s ∈ {+1, −1} — знак v; для d = c (v = 0) используется s = 0, чтобы узел был один.
- Ребро: `(k_from, k_to, cost, mode)`, cost = |Δv| / a_max, mode ∈ {+1, −1}.

Граф **ориентированный**: из-за дрейфа двигаться по параболе можно только в сторону роста v для «+» и убывания v для «−».

## 4. Алгоритм

1. **Сетка.** Равномерные C и D с шагом h, плюс параболы старта и цели.
2. **Узлы.** Для всех пар (c_i, d_j) с d_j ≥ c_i — одна или две точки пересечения. Опционально отбросить |v| > v_max.
3. **Рёбра вдоль траекторий.** Для каждой «+» параболы отсортировать её узлы по возрастанию v и соединить соседей; для каждой «−» — по убыванию v. Движение между соседними узлами точное, никакой интеграции не нужно.
4. **Переключения.** Узел принадлежит одновременно «+» и «−» параболе, поэтому переключение в нём бесплатно (для быстродействия). Если нужен штраф за переключение — состояние поиска становится (узел, текущий режим).
5. **Функция цены.** Обратный Дейкстра от цели: T(узел) и policy(узел) = (режим, следующий узел).
6. **Запрос из произвольной точки.** Найти ячейку по (c, d, sign v), билинейно интерполировать T по четырём углам. Управление — режим с лучшим продолжением (или режим ближайшего угла).
7. **Проверка.** Сравнить с аналитическим временем T*(x, v).

## 5. Аналитический эталон

Кривая переключения: x = −v|v| / (2a_max).

- выше неё (x + v|v|/(2a) > 0): сначала −a, потом +a, T* = (v + 2√(a·x + v²/2)) / a;
- ниже: сначала +a, потом −a, T* = (−v + 2√(−a·x + v²/2)) / a.

## 6. Код (Python, проверен)

```python
import numpy as np, heapq
from collections import defaultdict

A = 1.0

def c_plus(x, v, a=A):  return x - v*v/(2*a)
def c_minus(x, v, a=A): return x + v*v/(2*a)

def key(i, j, s, C, D):
    return (i, j, 0) if np.isclose(C[i], D[j]) else (i, j, s)

def build_lattice(C, D, a=A, vmax=None):
    nodes = {}
    for i, c in enumerate(C):
        for j, d in enumerate(D):
            if d < c and not np.isclose(d, c):
                continue
            for s in (+1, -1):
                k = key(i, j, s, C, D)
                if k in nodes:
                    continue
                v = s * np.sqrt(max(a * (d - c), 0.0))
                if vmax is not None and abs(v) > vmax:
                    continue
                nodes[k] = ((c + d) / 2, v)
    return nodes

def build_edges(nodes, a=A):
    plus, minus = defaultdict(list), defaultdict(list)
    for k, (x, v) in nodes.items():
        i, j, _ = k
        plus[i].append((v, k))
        minus[j].append((v, k))
    edges = defaultdict(list)
    for lst in plus.values():
        lst.sort()
        for (v1, k1), (v2, k2) in zip(lst, lst[1:]):
            edges[k1].append((k2, (v2 - v1) / a, +1))
    for lst in minus.values():
        lst.sort(reverse=True)
        for (v1, k1), (v2, k2) in zip(lst, lst[1:]):
            edges[k1].append((k2, (v1 - v2) / a, -1))
    return edges

def cost_to_go(edges, goal):
    rev = defaultdict(list)
    for k, lst in edges.items():
        for k2, cost, m in lst:
            rev[k2].append((k, cost, m))
    T, policy = {goal: 0.0}, {}
    pq = [(0.0, goal)]
    while pq:
        t, k = heapq.heappop(pq)
        if t > T[k]:
            continue
        for k0, cost, m in rev[k]:
            if t + cost < T.get(k0, np.inf):
                T[k0] = t + cost
                policy[k0] = (m, k)
                heapq.heappush(pq, (t + cost, k0))
    return T, policy

def T_star(x, v, a=A):
    if x + v * abs(v) / (2 * a) > 0:
        return (v + 2 * np.sqrt(a * x + v * v / 2)) / a
    return (-v + 2 * np.sqrt(-a * x + v * v / 2)) / a

def interp_T(x, v, C, D, T, a=A):
    c, d, s = c_plus(x, v, a), c_minus(x, v, a), (1 if v >= 0 else -1)
    i = np.searchsorted(C, c) - 1
    j = np.searchsorted(D, d) - 1
    if i < 0 or j < 0 or i + 1 >= len(C) or j + 1 >= len(D):
        return np.nan
    corners = [(i, j), (i + 1, j), (i, j + 1), (i + 1, j + 1)]
    vals = [T.get(key(ii, jj, s, C, D)) for ii, jj in corners]
    if any(t is None for t in vals):
        return np.nan
    u = (c - C[i]) / (C[i + 1] - C[i])
    w = (d - D[j]) / (D[j + 1] - D[j])
    return ((1-u)*(1-w)*vals[0] + u*(1-w)*vals[1]
            + (1-u)*w*vals[2] + u*w*vals[3])

if __name__ == "__main__":
    C = np.linspace(-4, 4, 81)
    D = C.copy()
    nodes = build_lattice(C, D)
    edges = build_edges(nodes)
    i0 = int(np.argmin(abs(C)))
    goal = key(i0, i0, 0, C, D)
    T, policy = cost_to_go(edges, goal)
    err = max(abs(T[k] - T_star(*nodes[k])) for k in T)
    print("nodes", len(nodes), "reached", len(T), "max node err", err)
    rng = np.random.default_rng(0)
    errs = []
    for _ in range(2000):
        x, v = rng.uniform(-1.5, 1.5), rng.uniform(-1.5, 1.5)
        ti = interp_T(x, v, C, D, T)
        if not np.isnan(ti):
            errs.append(abs(ti - T_star(x, v)))
    errs = np.array(errs)
    print("interp: n", len(errs), "mean", errs.mean(), "max", errs.max())
```

Результат запуска (сетка 81 × 81 на [−4, 4], a_max = 1, цель — начало координат):

```
nodes 6561 reached 6561 max node err 2.98e-08
interp: mean 0.0099  max 0.236
```

- **В узлах ошибка на уровне машинной точности.** Это не случайность: оптимальный путь имеет одно переключение, и обе нужные параболы (своя d-парабола узла и c = 0 цели) есть в сетке. Если здесь ошибка заметная — баг в построении графа.
- **Между узлами ошибка — только от интерполяции.** Около оси v = 0 (|v| < 0.3) средняя ошибка ≈ 0.069, вдали ≈ 0.006, то есть в 10 раз меньше. Максимумы вдали сидят у кривой переключения, где у T излом.

## 7. Что улучшить

**Складка v = 0.** Варианты:
- рядом с осью интерполировать в (c, v) вместо (c, d) — там отображение гладкое;
- сгущать сетку по d − c около нуля (например, d − c = (k·Δ)², тогда v равномерно);
- хранить T отдельно для двух половин плоскости и не интерполировать через ось.

**Излом на кривой переключения.** Билинейная интерполяция сглаживает излом. Можно брать для ячейки минимум из двух интерполянтов — по «+» продолжению и по «−» — это эквивалент min в уравнении Беллмана.

**Адаптивный размер спор.** Проверять ошибку в центрах ячеек (T_interp против T по графу, достроенному через точку центра) и дробить ячейку, если ошибка больше допуска. Это и есть «максимальный объём споры при ограничении на ошибку» из обсуждения, только ограничение ставится на функцию цены, а не на геометрию.

**Ограничение скорости |v| ≤ v_max.** Добавить третий режим a = 0 на прямых v = ±v_max: узлы — пересечения этих прямых с параболами, рёбра — отрезки прямых с cost = |Δx| / v_max. Около v = 0 режим a = 0 не нужен (там он вырождается).

**Произвольная цель.** Если цель — множество, добавить в сетку параболы через несколько точек его границы; точности в узлах больше не гарантировано, это первый реалистичный тест качества покрытия.

## 8. Как обобщить на дифдрайв

Интерфейс режима — то, что меняется от системы к системе:

```python
class Mode:
    def to_chart(self, state):   # -> (номер траектории, координата вдоль)
        ...
    def from_chart(self, label, s):  # -> state
        ...
    def speed_along(self):       # ds/dt, чтобы считать стоимость
        ...
```

| Режим дифдрайва | Номер траектории | Вдоль |
|---|---|---|
| v = ±v_max, ω = 0 | (n, θ) — боковое смещение и курс | s — путь вдоль курса |
| v = 0, ω = ±ω_max | (x, y) | θ |
| v = ±v_max, ω = ±ω_max | центр окружности (x_c, y_c) | θ |

Отличие от двойного интегратора: семейства трёхмерные, и пересечения траекторий разных режимов уже не образуют аккуратную решётку. Поэтому узлы берутся как выборка состояний (state lattice), а рёбра между ними строятся через `to_chart` / `from_chart` точно. Всё остальное — Дейкстра, интерполяция цены в спорах, адаптивное дробление — остаётся тем же.
