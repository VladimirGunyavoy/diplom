Путь f2b идёт 54 шага до цели; f2bc через 31 шаг заходит в точку q=(−2.83, −0.04, 0.31, −0.28) с gfree 0.021 (V* там 5.54 конечно), где агент с gfree застревает (inf). ## Заготовка ДИ 4D целиком (COVAFF=1, MAXC 1600×4, 2.81M узлов; b11, решение research-26: цель < 347 с = PPO)
Разбивка (замер `solve всего` по таймерам в `growN.solve`): **build 281 с** (CPU, 4 слоя параллельно) + **solve 249 с** = **530 с**; в solve: стенсилы 4 u по ~37 с = 179 с (первый 69 с с постройкой индекса), SBCAUS 2 с, GPU-Якоби 130 проходов + перенос 68 с. До цели не хватает ~185 с.
**GPU-профиль стенсилов** (1M точек, 10.1M пар, STGPU=1): 17.3 с = `query` (Python-цикл по бинам, repeat/tile) 12.9 с (75%) из которых `_test_gpu` 5.8 с; `stencils` self 2.5 с (сборка IDX/W).
**QFAST=1** (флаг, по умолч. 0; `query_fast`: CSR бинов + векторная раздача пар, набор пар идентичен проверен): 300k точек 6.76→4.03 с (−40%), 1M точек 17.3→14.2 с (−18%); в полном solve ДИ 4D 249→243 с (−2%) — на всей массе узлов накладные расходы цикла по бинам уже были размазаны. Остаток 1M: `query_fast` 9.1 с (из них `_test_gpu` 5.5 с, раздача пар ~3.6 с), `stencils` self 3.2 с.
Вывод: стенсилы — потолок ~37 с/u из-за 10M пар на 1M узлов (~10 пар на узел, Ньютон на GPU 5.5 с + CPU-раздача); одними микроправками 530→<347 не достичь. Кандидаты на дальнейшее (не сделаны): (1) Якоби с тёплого старта/мягче допуск (−30..50 с из 68); (2) конвейер build→стенсилы по слоям (стенсилы u начинаются, когда готовы слои, перекрытие с CPU-сборкой, −100 с и более); (3) меньше узлов (MAXC/покрытие) или PREFK (−26% Ньютона, неточно); (4) раздача пар на GPU целиком (убрать CPU-повтор/IDX/W, ~−10 с/u).

### Профиль роста слоя ДИ 4D при COVAFF=1 (MAXC 1500, cProfile 196 с): следующий топ
`covered` всё ещё 140 из 196 с (71%): `query`+`_test` — 52 775 вызовов (~1.7 мс каждый, мелкие пакеты граней), `_test` self 65 с (аффинный einsum и фильтр по ящику), `ufunc.reduce` 19 с, `np.array` 15 с, `einsum` 14 с, `query` self 11 с, `mlin` 11 с. Время теперь — накладные расходы мелких вызовов, а не Ньютон. Пути: (1) собрать грани по направлениям в один вызов `covered` (батч ×10–30 меньше вызовов); (2) инкрементальный CSR для `query_fast` (сейчас пересборка на каждом `add`); (3) воксельная карта «покрыто ядром» вместо поиска по ячейкам (приближённо).
