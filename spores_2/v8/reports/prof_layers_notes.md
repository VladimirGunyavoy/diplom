# prof_layers — выводы и предложения по ускорению (worker-1, growN.py не правился)

Данные — `prof_layers.md` / `.json` (прогон на **aida**, `nice 5`, машина свободна, 3 повтора дали одинаковые времена). Скрипт: `tests/prof_layers.py`.

## Главное

| где | u=+1 | u=−1 | u=0 | три слоя |
|---|---|---|---|---|
| **aida** (чистый прогон, rng 0) | 0.44 с | 0.44 с | 1.38 с | **2.25 с** |
| ноут, Windows-питон через /mnt/c, под нагрузкой (4 агента + окно) | 0.9–1.2 с | 1.1–5.3 с | 4.6–14 с | 6–26 с |

- Цель «три слоя < 3 с, слой < 1 с» на aida уже выполнена, кроме слоя u=0 (1.38 с). Те «26 с» — это ноут под нагрузкой (разброс одного и того же прогона 4.6–14 с на u=0 в течение получаса), а не рост работы алгоритма: число вызовов то же. Для замеров рядом с окном брать минимум из нескольких прогонов или aida.
- **Слой u=0 = 61% времени** (1.38 из 2.25 с). Причина: **38 из 45 вызовов growN отвергаются** (клетка «too few rows / narrow cell»), а решётка строк (а) строится для них полностью. На ноуте: отвергнутые вызовы 8.9 с из 12.6 с слоя (0.23 с на вызов против 0.17 с на принятую клетку); принятых клеток всего 7. Для u=±1 отвергнутых нет (12/12, 11/11).

## Предложения по убыванию выигрыша

1. **Точный поток ДИ вместо rk4 (проверено).** Для di (`ẋ = v, v̇ = u`, u постоянно на шаге) `rk4`, `_rkv` и `jac` заменяются замкнутой формой `x + vT + uT²/2, v + uT` и константной `jac = [[0,1],[0,0]]` — одна подмена в `growN.py` под `if SYS == 'di'`. Я проверил подменой снаружи (`scratch/prof_closedform_aida.py`, growN не тронут): клетки те же (12 / 11 / 7), контрольная сумма узлов совпадает до 6·10⁻¹³; **aida: 2.33 → 1.18 с (−49%)**, u=0: 1.42 → 0.47 с, u=±1: 0.45 → 0.36 с. Затрагивает (а), (б), (е) разом (rk4 — первая строка топа по tottime).
2. **Отвергнутые споры на u=0 — не строить решётку целиком** (оценка: u=0 ещё −0.2…−0.4 с после п.1, на ноуте больше, т.к. 70% слоя). Решётка (а) считается сразу на 2·nmax строк в обе стороны (nmax = 60, шаг адаптивный до HMAX = 1.0 → до 20 подшагов на строку) для 41 узла; принятая клетка использует nb+nf ≈ 16–20 строк. Варианты: (i) считать строки блоками по ~8 и достраивать по мере роста клетки (как уже сделано для NORMFRONT через `nf_fill`); (ii) ранний отказ до решётки: оценка числа строк по скорости потока вдоль зерна (на u=0 поле почти стоит у v≈0) и по расстоянию до границы поля/готовых клеток; (iii) не посылать в growN «dead»-затравки повторно (`RMINZ` уже есть, но 38 отказов на 7 клеток показывают, что очередь пересеивает непригодные точки).
3. **NORMFRONT: достраивать окно, а не пересчитывать** (оценка: −0.15…−0.2 с на aida, (б) 26%). `nf_fill` вызывается 174 раза на 68 growN и каждый раз заново прогоняет все `nr` строк по расширенному окну; считать только новые узлы окна и новые строки. В `nf1_rows` скалярные циклы `for j in range(ia+1, L)` по узлам — линейная рекуррентность: выносится в векторную форму (`np.cumsum`/`cumprod`) или хотя бы выход из Ньютона по допуску 1e-8 вместо 1e-11 (обычно 2–3 итерации из 5); `np.nan_to_num` (14 119 вызовов) убрать, заменив `where` на делителе.
4. **HexIdx.covered/inside — пакетами** (оценка: −0.1…−0.15 с, (г) 21%). 3 171 + 1 838 вызовов, многие по одной точке (`idx.covered(p[None])` на каждую затравку; в `growN` проверки зацепа по узлам); собрать точки затравок/проб в массив и звать раз на пакет; `_prep` (4 361 вызов, на каждый `_test`) кэшировать между вызовами, пока `idx.n` не изменился.
5. **covcheck: пакетный посев проб** (оценка: −0.05…−0.1 с, (д) 8%). `rand_seed` 15 004 вызова в python-цикле — один `rng.uniform(size=(COVP, N))` и векторные `inbox/ingoal/slowf`.
6. **f/Bq/jac без `np.stack`** (оценка: −0.05 с после п.1; 13 173 `np.stack`, 698 693 `np.empty`): для di `f` уже без stack; остальное закрывается п.1.

Ожидаемый итог (aida): п.1 даёт 1.2 с на три слоя; п.2–5 вместе доводят до ≈ 0.7–0.9 с (слой u=0 < 0.3 с). Для ноута эффект пропорционален (ноут в 2–7 раз медленнее aida под нагрузкой).

## Ограничения измерений
- Профиль cProfile раздувает мелкие вызовы (×1.4 на aida: 3.1 с против 2.25 с), доли по cumtime, а не по секундам из чистых прогонов.
- rng(0) на каждый слой; в окне rng(k) — клетки чуть другие (порядок слоёв и покрытие те же по счёту клеток: 12 / 11 / 7 на aida для rng(0)).
- Сравнение «замкнутая форма» делал подменой функций извне и сверкой результатов; в `growN.py` ничего не менял (его правит worker-2).
