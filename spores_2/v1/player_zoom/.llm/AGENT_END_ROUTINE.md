  ```bash

  - что изменилось 1
  - что изменилось 2
  ```

  **Примеры хороших сообщений:**
  - `[Zoom]: fix invariant point calculation for edge cases`
  - `[Refactor]: extract ColorManager to separate module`
  - `[Docs]: update LLM context with new architecture`

- [ ] **НЕ пушить автоматически**
  - Пуш только если пользователь **явно попросил**

## 🎯 Важные напоминания

### ⚠️ Git Safety:
- ❌ Никогда не используй `git add .` или `git add -A` - можешь случайно добавить .env или другие чувствительные файлы
- ❌ Не используй `--force` флаги без явного запроса
- ❌ Не делай `git reset --hard` без явного запроса
- ✅ Всегда показывай `git status` перед коммитом

### 📝 Changelog:
- Пиши **ЧТО** и **ПОЧЕМУ**, а не только "обновил файл X"
- Добавляй ссылки на git commits для трейсабилити
- Группируй связанные изменения вместе

### 🔄 State files:
- `current.md` - должен отражать **реальность** (не мечты)
- `issues.md` - проблемы должны быть **воспроизводимы**
- `plan.md` - задачи должны быть **actionable**
